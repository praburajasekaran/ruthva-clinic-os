# Send Worker emails with Amazon SES

The app is hosted on Cloudflare Workers, D1, and R2. Amazon SES replaces Cloudflare Email Service at the user's request. The configured region is `us-east-1`, and the sender is `noreply@ruthva.com`. The SES console confirms the verified domain, a quota of 50,000 emails per 24 hours, and a maximum send rate of 14 emails per second.

## Grounding

`sendEmail(env, to, subject, html)` is used by OTP signup and login, staff invitations, and the reminder outbox. Callers receive `{ messageId }`. OTP callers remove the pending code on provider failure. Invitations record `email_sent=false`. Reminders release the lease and retry later. Provider replacement belongs behind that contract.

## Design candidates

| Candidate | Shape | Assessment |
| --- | --- | --- |
| AWS SDK SESv2 | SESv2 client, command types, and a Fetch HTTP handler. | Official SDK, but adds client and runtime plumbing for one API call. |
| SESv2 HTTPS with `aws4fetch` | Existing sender arguments become the SES JSON payload. A maintained SigV4 signer signs one request. | Selected. Works with Workers Fetch and Web Crypto, and preserves the existing caller contract. |

The sender module exposes `sendEmail(env, to, subject, html): Promise<{ messageId: string }>` and owns SES credentials, signing, timeout, and response parsing. It removes the Cloudflare `EMAIL` binding. It keeps local capture mode and accepts optional AWS session credentials. Automatic HTTP retries are disabled because SES SendEmail has no idempotency token. The existing D1 reminder outbox controls retries.

The first implementation used signed mock requests because AWS credentials were absent. The user later approved a dedicated SES-only IAM user and storage of its access key in Worker secrets. The user `ruthva-cloudflare-ses` has no console access. Its one inline policy matches `worker/ses-policy.json` and restricts `ses:SendEmail` to the verified identity and configured sender.

## Verification

`rtk npm test` passes all ten workerd scenarios and five migration tests. Every normal transactional email request in the runtime suite uses the SES signer against a mock provider. The SES scenario rejects throttling, invalid receipts, redirects, and rejected deliveries without retrying or retaining an unused OTP. Reminder audits preserve the SES message ID.

`rtk npm run check` passes with the existing Next font warning. The API dry deployment passes with the SES module.

The deployed API passes five live SES scenarios through `.audit/cloudflare-ses-smoke.mjs`. Invitations, registered-user OTPs, and a reminder are accepted by the mailbox simulator. The reminder audit stores the real SES message ID. Repeating the reminder sends zero messages. A request from a sender outside the IAM condition returns HTTP 403. The deployed browser also displays the verification-code form after an OTP request.

No customer messages were sent. Human inbox placement remains unverified. Cron Triggers remain disabled during staging. The final deployed API version is `41b9188f-97dc-4af6-b341-337bd8960936`. Details and evidence are recorded in `docs/cloudflare-verification.md`.
